What actually happened

In UTF-8, é is two bytes: 0xC3 0xA9. A program that reads those bytes as Windows-1252 (or Latin-1) does not see one letter - it sees two characters, Ã and ©, and writes both. That is why the damage always starts with Ã or Â: those are the byte values 0xC3 and 0xC2, the two bytes UTF-8 uses most for accented Latin letters.

The important part: each of those characters still stands for exactly one original byte. Nothing was replaced or dropped, so the text can be walked back byte by byte and decoded again as UTF-8. This is not a guess at what the name probably was - the original bytes are still in the string.

Is my file corrupted?

No. Double encoding keeps every byte: in UTF-8 the letter é is the two bytes 0xC3 0xA9, and a tool that read those bytes as Windows-1252 simply drew two characters for them. Nothing was replaced or thrown away, so the original bytes can be read again. A corrupted file is one where the bytes were overwritten - that is the question-mark case, and it is different.

Why does the damage always start with Ã or Â?

Because those are the byte values 0xC3 and 0xC2, which is what UTF-8 uses in front of most accented Latin letters. Every é, ñ, ü, è and ö in a UTF-8 file is written as one of those two bytes plus a second byte, so a reader that assumes Windows-1252 shows a pair of characters instead of one letter.
