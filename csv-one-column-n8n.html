n8n read your whole CSV as one column named name;email;company;topic

Nothing is corrupted. Your file is semicolon or tab separated and the parser was told comma, so it found no commas and every line became one field. Here is how to tell which separator you have, the node that sniffs it, and what it actually did to one 12-lead list saved three ways.

Why the header becomes a column name

A CSV parser reads the first line, counts the separator in it, and names the columns after the pieces. Feed it a header that contains no commas and the line is one piece — so the column is called name;email;company;topic and every row under it holds an entire record as text. Nothing in the values is damaged; the split simply never happened.

Two files cause almost all of it, and neither is exotic:

  • A European Excel exportExcel writes the list separator from the machine regional settings. Where the decimal separator is a comma, the list separator is a semicolon — so the file is a perfectly valid CSV with ; between fields and commas inside them.
  • A range copied out of Excel or Google SheetsThe clipboard format between spreadsheet cells is tab separated. Pasted into a file and saved, it is a TSV wearing a .csv extension.

The cheap test takes ten seconds and no tool: open the file in a text editor. name;email;company;topic is semicolon separated, the same words with wide gaps are tab separated.

The node, in full

Code node, Run Once for All Items, mode JavaScript. Input: one item whose json.data is the raw file text, which is what Read/Download a file hands you. It prints the separator it chose and the shape it produced, so a wrong guess is visible in the node output instead of silently producing a single column. No credential, no network call, nothing written.

// Detect the delimiter, then parse as a table. Run Once for All Items.
// Input: one item whose json.data is the raw file text (from Read/Download a file).
function csvRecords(text, delim) {
  var s = String(text || '').replace(/\r\n?/g, '\n');
  var out = [], cells = [], cur = '', q = false;
  for (var i = 0; i < s.length; i++) {
    var c = s.charAt(i);
    if (q) {
      if (c === '"') { if (s.charAt(i + 1) === '"') { cur += '"'; i++; } else { q = false; } }
      else { cur += c; }
    } else if (c === '"') { q = true; }
    else if (c === delim) { cells.push(cur); cur = ''; }
    else if (c === '\n') { cells.push(cur); out.push(cells); cells = []; cur = ''; }
    else { cur += c; }
  }
  cells.push(cur);
  out.push(cells);
  return out.filter(function (r) { return r.some(function (v) { return String(v).trim() !== ''; }); });
}

function pickDelimiter(text) {
  var best = ',', bestScore = -1;
  [',', ';', '\t'].forEach(function (d) {
    var recs = csvRecords(text, d);
    if (!recs.length) return;
    var counts = {}, modal = 0, modalCount = 0;
    recs.forEach(function (r) {
      var n = r.length;
      counts[n] = (counts[n] || 0) + 1;
      if (counts[n] > modalCount) { modalCount = counts[n]; modal = n; }
    });
    if (modal < 2) return;
    var score = (modal - 1) * (modalCount / recs.length);
    if (score > bestScore) { bestScore = score; best = d; }
  });
  return best;
}

const raw = items[0].json.data;
const delim = pickDelimiter(raw);
const recs = csvRecords(raw, delim);
const head = recs.shift().map(h => String(h).trim());
const rows = recs.map(r => {
  const o = {};
  head.forEach((h, i) => { o[h || 'column_' + (i + 1)] = String(r[i] == null ? '' : r[i]).trim(); });
  return { json: o };
});
console.log('delimiter', JSON.stringify(delim), 'columns', head.length, 'rows', rows.length);
return rows;

How it decides: for each candidate separator it counts how many fields each line splits into, takes the most common count, and scores it by that count weighted by how many lines agree. A single column scores nothing, so the default stays comma and a genuinely one-column file comes back unchanged rather than mangled. Quotes are handled — a separator inside a quoted field is text, and "" inside a quoted field is one quote character.

Why 12 rows and not 13

One row of the export is ;;; — separators and nothing else, a blank line the source system kept. The node drops a row only when every cell in it is empty, so that line never becomes a lead with an empty address. The semicolon copy has 14 lines because the blank row survives as punctuation; the tab copy has 13 because a row of tab characters is whitespace and the file writer dropped it. Both end at 12 records, which is the honest number.

The same rule means a footer, a total line or a stray blank at the end never lands in your CRM as a record — and it also means a real lead whose every field is blank is indistinguishable from noise, because it is.

What this does not fix

  • A file with no separator at allA true one-column export, or a fixed-width report. Nothing to detect, nothing to split; the node returns it as-is and that is the correct answer.
  • Pipe or other exotic separatorsOnly comma, semicolon and tab are tried, because those are what spreadsheet, CRM and form-tool exports write. A pipe-separated file is one string added to the candidate list, or convert it first.
  • Damaged quotingA file where a quote is never closed will swallow the rest of the file into one field. The sniffer cannot see that the quoting is wrong, only which separator fits best.
  • Two header rows, or a title row above the headerThe node trusts line one. If line one is a report title, you get a table whose columns are named after the title, and the real header becomes a data row. Remove it, or skip the first N lines before the node.
  • EncodingSeparate problem, separate fix: if the values contain question marks or Ã©-style pairs, no delimiter change helps. See the encoding page.

Questions this page gets

Why does n8n put my whole CSV into one column?

The file is not comma separated. A European Excel export writes the list separator from the machine regional settings, which is a semicolon where the decimal separator is a comma; a range copied out of Excel or Google Sheets is tab separated. A parser that only counts commas finds none in the header line, so the line becomes one field and its name is the entire header.

How do I know my file is semicolon separated?

Open it in a plain text editor, not a spreadsheet. The first line reads name;email;company;topic. The browser repair page shows the same thing before it converts anything, and the code on this page prints the delimiter it chose.

Is one column named name;email;company;topic the same as an encoding problem?

No. Encoding damage shows up inside the values: question marks, or letters like Ã© instead of e-accent. Here the values are intact and only the split is wrong, so nothing is lost and re-exporting or re-splitting it gives the whole table back.

Can I just save the file as CSV again?

Yes, if you still have the spreadsheet: use Save As and pick the comma variant explicitly, then reopen it. If the file came from a client or a system you do not control, split it yourself with the node below, or convert it in the browser without uploading it anywhere.

Does the sniffer break a file that really has one column?

No. A file where every line has one field scores nothing for any delimiter, so the node falls back to comma and returns the single column as it is. A one-column export is a genuinely different problem and this node cannot split what has no separator in it.

What about pipe-separated or space-aligned files?

Not handled. The sniffer tries comma, semicolon and tab because those are what spreadsheet and CRM exports actually write. A pipe-separated file needs the delimiter added to the list, one string, or a conversion first.
