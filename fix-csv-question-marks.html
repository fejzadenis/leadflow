What actually happened

Excel on a Serbian, Croatian, Polish, Czech or Hungarian Windows writes CSV in Windows-1250, and on most Western European Windows in Windows-1252. Almost every tool that reads CSV afterwards - n8n, Python, Google Sheets, a CRM importer - assumes UTF-8 unless it is told otherwise. The bytes above 0x7F are not valid UTF-8, so they get replaced: by a question mark in some tools, by a black diamond � in others.

Questions people ask

Is the file corrupted, or just decoded wrong?

Decoded wrong, in almost every case. Excel wrote the CSV in Windows-1250 or Windows-1252 and the next tool read it as UTF-8. The bytes for the accented letters are still in the file, they are just not valid UTF-8, so the reader replaces each one with a question mark or a black diamond. Decoding the same bytes with the right code page brings the letters back.

Does the free tool upload my list anywhere?

No. It is one HTML file that runs in the tab: the file is read with the browser's own file API, decoded locally and written back to a download. There is no fetch, no XHR, no analytics and no storage. You can open the page source and search for network calls - there are none.

Will it fix a file where the letters are already question marks?

Only if the original bytes are still there. If a program replaced the characters with a literal ? and then saved that file, the information is gone and no tool can restore it - the page will clean the rest of the file and say so. If the export still holds the original bytes (the usual case), the letters come back.

Which languages does it handle?

The letters of Central and Eastern Europe (č ć ž š đ, ł ą ę, ř ě ů) and Western Europe (é è ü ö ñ). It offers Windows-1250 and Windows-1252, because those are the two code pages Excel picks by Windows region and nothing in the file records which one was used. A Cyrillic (1251) or Greek (1253) export needs a different code page and will still come out wrong - the page does not pretend otherwise.

Why not just re-save the file as CSV UTF-8 in Excel?

That is the right move when you still have the file open in Excel and the letters look correct there. It does not work on a file that already contains the damage, and it does not work when the export is sent to you by somebody else's Excel. For those, re-save the cleaned copy you get from the browser tool.
