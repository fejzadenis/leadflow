LeadFlow Automation Pack (n8n)

Four ready-to-import n8n workflows for B2B lead generation — compliant by design (no LinkedIn scraping, no account bans) — plus a zero-setup demo that runs with no credentials.

What's inside

FilePurpose
workflows/00-quick-demo.jsonZero-setup demo: 6 messy rows → clean leads, patterns, drafts (no credentials, no network)
workflows/01-lead-import-csv.jsonCSV → dedupe by email → Google Sheets
workflows/02-webhook-lead-capture.jsonWebhook (any form) → Google Sheets
workflows/03-ai-email-drafter.jsonLeads → AI-personalized email drafts (DeepSeek) → Google Sheets
workflows/04-email-patterns.jsonLeads → generate candidate email patterns (FREE, no API) → Google Sheets

Requirements

  • n8n (self-hosted Community = free, or n8n Cloud).
  • Google account (Sheets) + a Google Sheets OAuth2 credential in n8n.
  • DeepSeek API key — ONLY for workflow 03. In n8n: Credentials → New → Header Auth: Name = Authorization, Value = Bearer <your_key>.

Setup

  1. Prove it runs first: import workflows/00-quick-demo.json and Execute it — no credentials, nothing written. Then configure the rest.
  2. n8n → Workflows → Import from File → choose each JSON.
  3. In your Google Sheet create three tabs: Sheet1 (your leads), Drafts (03 writes here), Email Patterns (04 writes here). Output tabs are separate on purpose — re-running a workflow can never treat generated rows as fresh leads.
  4. Open each Google Sheets node → replace the placeholder spreadsheet (YOUR_GOOGLE_SHEET_ID) with your file, pick the tab listed above, then choose your Google Sheets credential.
  5. Workflow 03 → select your DeepSeek (Header Auth) credential.
  6. Save, then click Execute workflow (each workflow starts from a Manual Trigger; #02 starts from its Webhook).
  7. Workflow 01's Load CSV node is preset to /home/node/.n8n-files/sample-data/leads-sample.csv, which the shipped Docker compose (setup/) mounts read-only - run it as imported. On npm or your own compose, n8n 2.x restricts file access to ~/.n8n-files (N8N_RESTRICT_FILE_ACCESS_TO): copy the CSV there or widen the variable, then point the node at your path. On n8n Cloud, file reads are limited to /home/node, so run 01 self-hosted and start Cloud users on 02/03/04.

Credentials needed

  • Google Sheets: OAuth2.
  • DeepSeek: Header Auth 'Authorization: Bearer <key>' (workflow 03 only).

Limitations

  • No LinkedIn scraping; leads come from your own CSV/forms.
  • Dedupe in workflow 01 works inside one import: the same address twice in your CSV is one lead. It does not read rows already in the sheet, so importing the same file twice against the same tab appends it twice - import into a fresh tab if you re-run a file.
  • Workflow 03 writes email DRAFTS to a sheet; it does NOT send email.
  • Workflow 04 generates candidate email patterns (unverified) — verify before sending.
  • 03 and 04 write to their own tabs (Drafts, Email Patterns) and skip rows that are already drafted/enriched, so re-runs are safe and idempotent.
  • Workflow 04 normalizes accented letters in names (e.g. 'Kovač' → 'kovac') and drops duplicates, so generated patterns are always valid local parts.
  • The target Google sheet must already exist; the sheet tab name is locale-dependent (e.g. 'Sheet1' or 'Лист1').

Troubleshooting

  • Setup errors (sheet not found, credential missing, 03 → 401, CSV path) are covered in TROUBLESHOOTING.md.

Costs

  • n8n self-hosted: $0. Google Sheets: $0.
  • DeepSeek: ~$0.50 per 1M tokens (negligible at normal volume).

INSTALL — running n8n for this pack

You need a working n8n instance. Any of these routes works; pick one.

Route A — n8n Cloud (fastest, no server)

  1. Create an account at n8n.cloud and open your instance.
  2. Continue with START-HERE.md (../START-HERE.md).

Route B — npm (local, no Docker)

  1. npm install -g n8n
  2. n8n start
  3. Open http://127.0.0.1:5678 (local only).

Notes: default DB is SQLite in ~/.n8n. Requires Node.js 20+.

Route C — Docker Compose (recommended for isolation)

  1. Install Docker Desktop (or Docker Engine on Linux/WSL2).
  2. In this setup/ folder: copy .env.example to .env and set N8N_ENCRYPTION_KEY to any long random string (keep it — it decrypts your stored credentials).
  3. docker compose up -d
  4. Open http://127.0.0.1:5678.

Optional in .env: GENERIC_TIMEZONE (default UTC).

The compose file already mounts this pack's sample-data/ folder read-only at /home/node/.n8n-files/sample-data - inside the folder n8n 2.x allows file nodes to read by default (N8N_RESTRICT_FILE_ACCESS_TO defaults to ~/.n8n-files). So workflow 01 reads its preset path without extra setup or env changes. Keep the compose file in setup/ (the mount path is relative to it). For Route B (npm), copy sample-data/leads-sample.csv into ~/.n8n-files/ instead.

Security (all routes)

  • Bind to 127.0.0.1 only (never 0.0.0.0).
  • Do not expose n8n to the internet without auth + TLS in front of it.
  • Keep your DeepSeek key in an n8n credential, not in workflow JSON.

After n8n is running

  • Go to ../START-HERE.md for the 15-minute pack setup.
  • Errors during setup: ../TROUBLESHOOTING.md.

TROUBLESHOOTING — LeadFlow Automation Pack

Every item below was hit (and fixed) during our own end-to-end testing. Check here before emailing support.

1. "Could not find the sheet" / no rows appear

  • The target Google Sheet must already exist. The pack does not create spreadsheets.
  • Open each Google Sheets node -> Document: pick your file by name -> Sheet: pick the tab.
  • Tab names are locale-dependent: Sheet1 on English accounts, Лист1/Hoja1 elsewhere. A mismatch fails silently with 0 rows written.

2. Credential errors on Google Sheets nodes

  • Importing a workflow does not import credentials. Every Sheets node ships with the placeholder YOUR_GOOGLE_SHEET_ID and no credential selected.
  • After import, open the node -> Credential -> "Create new" (OAuth2) or select an existing one -> sign in with the Google account that owns the sheet.
  • The sheet must be shared with that same account (or "Anyone with the link: Editor" for testing only).

3. Workflow 03 returns HTTP 401 from api.deepseek.com

  • 401 means the API key itself is invalid, not the node. Verify the key at platform.deepseek.com (Billing must show a positive balance; free-tier keys expire).
  • Credential type must be Header Auth: Name = Authorization, Value = Bearer sk-... (the word "Bearer" plus one space, then the key). A missing "Bearer" prefix also yields 401.
  • Workflows 01, 02 and 04 need no API key. If 03 is blocked, the pack still delivers value.

4. Workflow 01 can't read the CSV (ENOENT, or "Access to the file is not allowed")

Two different causes, same node - check which error you get.

"Access to the file is not allowed." (n8n 2.x, the default)

  • n8n 2.x only lets file nodes read inside ~/.n8n-files unless you change N8N_RESTRICT_FILE_ACCESS_TO. That is why our sample CSV is mounted at /home/node/.n8n-files/sample-data/, not at /data/.
  • Docker route (shipped setup/docker-compose.yml): nothing to do - the folder is mounted there read-only and the node is preset to it.
  • Your own compose file: add the same mount yourself (- ./sample-data:/home/node/.n8n-files/sample-data:ro).
  • npm / bare-metal: copy the CSV into ~/.n8n-files/, or set N8N_RESTRICT_FILE_ACCESS_TO to the folder holding it, then point the node at that absolute path.
  • n8n Cloud cannot read this file at all (reads are limited to /home/node). Run workflow 01 on self-hosted n8n, or skip the CSV step on Cloud and start from 02/03/04 with your leads already in the sheet.

"ENOENT: no such file or directory"

  • The path is read by the n8n process, not your laptop. It must exist inside the container (Docker) or on the host where n8n runs (npm).
  • Windows hosts: use forward slashes (C:/Users/you/leads.csv).
  • Header mismatch: the CSV columns must match the sheet columns (firstName, lastName, company, domain, email, topic).

5. Import fails / workflow looks empty

  • Use a current n8n: the pack is built and tested on n8n 2.x (2.47.4). Old 1.x builds lack the typeVersion of some shipped nodes (Google Sheets 4.5, Read/Write Files 1.1, Extract from File 1.2).
  • Import each JSON separately (Workflows -> Import from File); do not paste all four into one editor.

6. Workflow 02 webhook does nothing

  • Webhooks only listen when the workflow is Active (toggle top-right). Manual "Execute workflow" waits for one test call only.
  • Test URL is /webhook-test/..., production URL is /webhook/... - use the right one for the mode.

7. Workflow 04 emails bounce

  • 04 guesses patterns (first.last@, firstlast@, f.last@, flast@, first@). They are unverified.
  • Verify with your own SMTP check or a verification service before sending. Sending to guessed addresses hurts your domain reputation.

8. Re-running 03 or 04 fills my leads tab with junk rows

  • Older builds appended output onto the same tab they read from, so a second run treated generated drafts/patterns as new leads.
  • Current build writes to dedicated tabs (Drafts, Email Patterns) and skips rows that already carry a draft or pattern field. If you imported an older build, re-import 03/04 and re-point the append node at its own tab.
  • Importing a fresh copy is safe: nothing is overwritten, only new rows are appended.

9. I imported the same CSV twice and my leads tab now has duplicates

  • Workflow 01 dedupes inside one import: the same address appearing twice in the CSV (different topic, upper case, stray spaces) becomes one row, and a row without an email is kept unless name + company repeat exactly.
  • It does not read the rows already in your sheet, so running the same file twice against the same tab appends it twice. If you re-run a file, import into a fresh tab, or delete the previously imported rows first.
  • Rows are passed through as they are in your CSV - the dedupe compares addresses trimmed and lowercased, it does not rewrite the cell value.
